# 0.5.55: proposals 4, 5 and 6

1. Install the APK matching your ordinary or Restore Test installation. The
   working FEX, client, source build and database remain installed.
2. Primary navigation has Play, Client, Server, Build, Controller and More.
   More opens Setup, Backups, Advanced or Diagnostics. Client keeps imports,
   updates, loader selection, connection and everyday display choices.
   Advanced keeps runtime experiments, dependency repair, raw launch results,
   legacy exports and the historical GameHub reference.
3. On Play, open **Currently playing with**. Confirm active client generation,
   recorded client version, loader hash, server build/generation and database.
   Unknown versions stay unknown; a server's expected version is separate.
   Staged client/server updates are labeled not active.
4. After successful play, stop both client and server. Choose **Save working
   combination** and save its complete ZIP outside app data. This is a full
   backup, including saved quick login, and can take several minutes.
   The saved-combination receipt appears only after the output stream closes
   successfully. Keep the ZIP; the receipt alone cannot restore the data.
5. After updating, compare active and saved identities. **Restore saved working
   combination** selects the complete ZIP and restores its client, loader,
   server/database, runtimes and settings together. Progress after the backup
   point is replaced. This uses the existing validated complete-session restore.
   External server data is outside this app and cannot be included.
6. Start a download/import, client preparation, PlayOnline update, server build
   or Play startup. Check the shared operation header, elapsed time and latest
   update. Tap the header for live recent progress. Server builds/startup also
   show the latest server log line. Disabled actions have prerequisite text.
7. Play and log out normally. The latest operation should be Completed; old
   failed operations are under Diagnostics → historical operation log. Cancel
   an operation and verify Cancelled. An interrupted app process should not
   be presented as a successful operation on the next launch.
