# 0.5.19: FEX x87 store condition flags

**Delivered:** original-signature APK and immutable runtime v3 are ready. All seven
push jobs in run `35933191991` pass. Real Thor rendering is the next check.

## Discovery

The 0.5.18 Thor export still fails visually, while its actual selected SSE2 math
routines pass 192 synthetic results. See [the evidence audit](draw-coverage-0519.md).
Broadening draw coverage exposed a separate error during ARM64 qualification:
the texture fixture rendered 144 expected pixels, and the observer counted all
378 draws / 1,512 vertices from the sampled frame, but all draws were ordinary
UP. The compiled fixture contains both indexed call sites. Source inspection
found an integer comparison, intervening x87 stores, then its conditional jump.

Pinned FEX 2510's `X87StackOptimization::SilenceNaN` inserts `_FCmp(Value, Value)`
while expanding x87 stores late in the IR pipeline. It then uses the host flags
to select a quiet NaN without restoring the previous NZCV. For a finite value,
this comparison sets equality, overwriting the flags from the preceding guest
integer comparison. x87 FST/FSTP must leave those integer flags unchanged.
The helper is used in full80 and strict64, matching both affected phone modes.

This is distinct from the earlier Windows/CPUID mismatch and the isolated math
worker's context-restoration issue. A passing arithmetic-only oracle did not
exercise a branch across a floating-point store. The broad observer itself uses
integer classification and was reporting the path it received.

Upstream removed the problematic helper as part of [reverting NaN propagation
changes](https://github.com/FEX-Emu/FEX/commit/bc6295a78dd8d4bff49eb7f567881bd92d10b860).
Our focused patch preserves the pinned runtime's strict64 contract and NaN
behavior: load NZCV before the helper's comparison, select the result, restore
NZCV, then return it. No driver, DXVK, client, loader or server changes.

## Regression and qualification

`tests/windows/x87-flags.c` is independent synthetic code. It places an integer
comparison before each of FST/FSTP float/double, then tests the nonzero condition.
It covers zero, positive and negative inputs: 12 cases. Native host execution
passes. The runtime builder reproduces 8 full80 / 4 strict64 failures with the previous
CPU-feature-corrected translator and requires zero failures with the new translator,
in full80 and strict64. It preserves both binary hashes and execution logs.
The fixture also runs in ordinary FEX/Box64 integration and native Windows.

The texture fixture additionally counts its actual UP/indexed16/indexed32 calls.
All three paths must execute 504 times, retain 144 pixel checks, and produce the
expected batch summaries and hook restoration. No failing assertion or timeout
is weakened. Earlier candidate runs and final receipts are recorded below.

This fixes a reproduced translator correctness defect. It is a candidate for
the Thor FFXI corruption; only the next real-device launch can establish that
it restores those menus and character rendering. World entry remains unverified.
