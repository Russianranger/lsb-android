# Beta 0.7.2: reclaim the original imported client on Thor

Install the original-signed `LSB-Android-0.7.2.apk` (versionCode 76) over your current standard LSB app. Do not uninstall or clear data. No files are removed on install. Main and the published Beta 0.7 APK remain preserved. Raw GitHub Actions APKs use disposable signing keys and cannot update your original-signed installation.

1. Confirm your existing character, connection and quick login are still present. Stop the client and managed server. Keep your original imported client ZIP or an existing verified external complete session/working-combination backup. You do not need to export another 40 GiB backup if you already have one.
2. Open **Client → Backup and recovery → Manage backups and storage → Copies → Original imported client files → Remove imported files…**. Review the size and choose **Verify and remove**. The one-time check scans the active client, validates its initialization receipt/critical binary hashes, then compares the contents of every imported file outside personal USER/usr settings with the prepared copy. This can take several minutes. Normal and repeat launches do not run this comparison.
3. If verification reports a different or missing file, the original is kept. A newer/unprepared import or an already updated preparation can differ legitimately; keep that source or prepare the matching import first. Finish/discard pending imports, staged repairs/updates or loader recovery before retrying. Cleanup never guesses that different files are disposable.
4. After success, **App files → App external files / lsb → session → current** should retain only small configuration/inventory/loader/removal metadata. The `client` payload is gone; **Internal data / files → rt → clients** retains the active working client and Windows environment. For the supplied screenshots, removing the original should reclaim roughly 14 GiB. Refresh totals; Android's own usage may take time to update. FEX/runtime files remain needed. If removal was interrupted after verification, finish **Copies → Interrupted backup removal** to reclaim its remaining space.
5. Launch normally, close, and repeat **Quick login**. Confirm your existing character and USER/usr settings. Start the same server and check existing accounts/characters. No source rebuild, runtime reinstall or redeployment is needed. Database checkpoints, restore/retention and compiler cache are untouched by cleanup.
6. Loader imports still work: a newly selected xiloader is retained as a small separate file and applied only to the prepared loader using its existing recovery transaction. Skip replacing a working loader just to test cleanup. PlayOnline updates and prerequisite repair still stage copies of the prepared client. Reimport a complete ZIP for **Prepare imported client** or full external launcher packages; with **Preserve current FFXI USER and PlayOnline usr settings** selected, the current prepared settings carry into that new import.
7. Complete session/working-combination backups made after cleanup include the prepared client, prefix, runtime, configuration, retained loader, server/database and settings, without recreating the original client. They restore using the existing format. Older full backups may restore both copies as they originally existed; cleanup is optional again afterward. Existing external exports stay under **Exports**. Do not restore over the working device solely to test this change.

Qualification includes complete backup/restore across separate app storage layouts after cleanup, subsequent imports preserving prepared personal settings, loader replacement, repair/update staging, content mismatch/missing-file/symlink protection, cancellation before removal, and interrupted-removal cleanup with the active client unchanged. Device launch/login and actual reclaimed space still require the focused Thor checks above.
