# Beta 0.7.1 storage fix: Thor checks

Install the original-signed `LSB-Android-0.7.1.apk` (versionCode 75) over the standard Beta 0.6/0.7 app. Do not uninstall or clear app data. The disposable CI signer cannot update the release-signed app. No server rebuild, redeployment, client import or preparation is needed.

1. Stop the client and server. Open **Manage backups and storage**. **App files** now includes the full internal data directory (files, cache, code_cache, no_backup, preferences, databases and unknown folders), device-protected data, and all app external files/cache/media/expansion volumes. Tap the totals to compare unique file sizes, allocated bytes and Android's own data/cache/code numbers. GB and GiB are both shown. Partial scans are identified rather than appearing complete.
2. Browse **Internal data / files**, `rt` and `server-runtime`, plus **App external files / lsb**. Folder sizes let you locate prepared-client copies, imported game data, compiler cache, checkpoints or restore staging. These generic folders are read-only. The **Copies** tab retains the existing allowlist and confirmation rules; its sizes are already included in the app totals. No cleanup happens automatically.
3. Open **Exports**. Your previous **Save working combination** receipt should appear. If it says access is unavailable, tap **Locate existing backup** and select the existing external ZIP in Android Files. This only grants access and records its location: it does not export, duplicate or restore the archive. Previously unrecorded exports can also be located this way.
4. If the accidental working-combination archive is unwanted, review its filename/size and use **Delete export…** after reconnecting it. Confirming permanently deletes that external archive only. Installed client/server data and characters stay in place. Providers without deletion support must be managed in Android Files.
5. Optionally create one new complete/working-combination backup only if you actually want another archive and have enough free space. After success it appears in **Exports**, retains access across app restart, and never creates an additional internal ZIP. Failed or cancelled exports are not registered as completed backups.
6. Confirm normal client launch/quick login and server start with the same existing character. Server acceleration remains on by default; startup and runtime code are unchanged. Existing full backups remain compatible, and database checkpoint/retention behavior is unchanged.

The reported 44 GB / 22 GB discrepancy cannot be reconstructed without your phone's totals. The old browser only measured selected copy locations. It did not include all data/cache/staging folders. Saving a working combination streamed to the selected external document, rather than keeping a second local ZIP. The new view exposes both sets of locations without adding them together twice. Android's volume-specific counters, filesystem allocation, running writes and GB/GiB units can still produce differences; tap totals to see the precise comparison.
